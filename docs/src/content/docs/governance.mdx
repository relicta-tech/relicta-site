The Change Governance Protocol (CGP) evaluates release risk and can apply configured policies to release decisions. In Relicta v4.2.0, governance is opt-in; start by enabling it in `.relicta.yaml` and reviewing the generated evaluation before relying on it in automation.

```yaml
governance:
  enabled: true
  strict_mode: false
  require_human_for_breaking: true
  require_human_for_security: true
  memory_enabled: true
```

The default memory location is `.relicta/governance/memory.json`. Set `memory_path` if you need another location. Check the configuration generated by your installed version for all available fields and defaults.

## Evaluate a release

```bash
relicta plan --analyze
relicta evaluate
```

Use `relicta evaluate` to inspect the governance decision and any required actions. A risk score is an aid to review, not a guarantee that a change is safe, complete, or compliant.

## Policies

CGP can apply policies configured in `.relicta.yaml` and policy files under the configured policy directory. The policy DSL supports conditions and actions such as requiring approval, blocking a release, or adding a warning. See the [CGP specification](/cgp-specification) for the policy model and examples.

## Approval and publication

Governance decisions and release actions are separate steps. Keep human review in the workflow for changes that need it, and protect automated release jobs with repository permissions and environment rules. Enabling strict mode changes how policy decisions affect release actions; verify the behavior in a non-production repository before relying on it.

CGP records and risk evaluations can support internal review, but they do not establish regulatory compliance on their own.
