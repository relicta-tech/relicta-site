Relicta v4.2.0 includes a [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) server. An MCP client can inspect release state, plan changes, generate notes, evaluate governance, and request release actions through the configured workflow.

## Customer notes from an agent session (unreleased)

Newer source contains a workflow for drafting customer-facing notes in a coding-agent conversation and saving that exact text to the release through MCP. It is not included in the published v4.2.0 CLI. Relicta stores agent-supplied text; it does not verify that the claims are accurate. Review notes before approval or publication.

## Start the server

```bash
# Local agent connection (stdio is the default)
relicta mcp serve

# HTTP, explicitly restricted to loopback
relicta mcp serve --transport http --address 127.0.0.1:8080
```

The v4.2.0 HTTP server does not provide built-in authentication or TLS. If you choose another bind address, restrict network access and place it behind a trusted proxy that provides authentication and TLS. Do not expose the server directly to an untrusted network.

## Claude Desktop example

Add the following to the Claude Desktop configuration file for your operating system, changing the project path:

```json
{
  "mcpServers": {
    "relicta": {
      "command": "relicta",
      "args": ["mcp", "serve"],
      "cwd": "/path/to/your/project"
    }
  }
}
```

Restart the client after saving the configuration. The server uses stdio by default, which is suitable for a local MCP client.

## Available capabilities

The v4.2.0 server exposes core tools for status, initialization, planning, version bumping, notes, governance evaluation, approval, and publishing. It also includes helper tools for blast-radius analysis, version inference, diff summaries, and release validation. The exact tool schemas are provided by the running MCP server; inspect them in your MCP client before building automation around them.

Read-only resources include current release state, configuration, recent commits, changelog, and the governance risk report.

## Safety

- Use stdio for local agent integrations where possible.
- Treat approval and publishing tools as actions that can change repository or release state.
- Use dry-run options when previewing supported operations.
- Keep API keys and plugin credentials in environment variables or a secret manager.
- Review agent-generated plans and notes before approving or publishing.
