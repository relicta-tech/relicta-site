Relicta v4.2.0 reads `.relicta.yaml` from the repository root by default. Create a starter file with `relicta init`, then adjust the options your workflow needs.

```yaml
versioning:
  strategy: conventional
  tag_prefix: v
  git_tag: true
  git_push: false

changelog:
  file: CHANGELOG.md
  format: markdown

workflow:
  require_approval: true

governance:
  enabled: false
```

Keep `git_push` disabled until you intentionally want Relicta to push tags. Review the generated plan and notes before approval and publication.

## Configuration file and flags

- Default file: `.relicta.yaml` in the repository root.
- `--config` (or `-c`): select a different configuration file.
- `--dry-run`: simulate actions without making changes.
- `--json`: emit machine-readable output.
- `--ci`: use CI mode (non-interactive, JSON output, and auto-approval behavior); review its effects before using it in a publishing job.

There is no global `--chdir` flag in the v4.2.0 CLI. Run the command from the repository directory, or use your CI action's `working-directory` input.

## Common sections

- **versioning**: version strategy, tag prefix, and Git tag/push behavior.
- **changelog**: changelog file and output format.
- **ai**: provider settings for AI-generated notes. `relicta notes --ai` requires a configured provider key; without `--ai`, notes are deterministic.
- **plugins**: integrations configured for release workflow steps. See [Plugins](/plugins).
- **workflow**: approval and branch-related workflow settings. A configured branch list should not be treated as an access-control boundary unless your CI or hosting platform enforces it.
- **governance**: optional CGP risk and policy settings. See [Governance](/governance).

The supported fields and defaults can vary by Relicta release. Use `relicta init` and the configuration generated by the version you install as the source of truth; do not copy options from unreleased documentation into a v4.2.0 project.

## Secrets

Keep provider and plugin credentials in environment variables or your CI secret store. Do not commit API keys or tokens in `.relicta.yaml`.

```yaml
ai:
  enabled: true
  provider: openai
  api_key: ${OPENAI_API_KEY}
```

For AI notes, the v4.2.0 CLI supports provider keys such as `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, and `OLLAMA_HOST`. Check the provider-specific guide for configuration details.
