This guide describes the published Relicta **v4.2.0** command line. The v5 source includes additional capabilities that are not part of the public release.

## Quick release

Use the dry run to preview the workflow. Run the live command only when you intend to prepare and publish a release:

```bash
relicta release --dry-run
relicta release
```

A live release runs **plan → bump → notes → approve → publish**. The default flow prompts for approval. `relicta release --yes` skips that prompt; use it only when an external CI or repository control supplies the approval required by your process.

## Step-by-step workflow

### 1. Plan

```bash
relicta plan
```

Relicta analyzes changes since the latest tag and recommends a semantic version. Useful v4.2.0 options include:

- `--from <ref>` and `--to <ref>` to select the analysis range.
- `--analyze` to classify commits and stop after analysis.
- `--no-ai` to disable AI-assisted classification.
- `--review` to review and adjust commit classifications before planning.
- `--json` for machine-readable output.

### 2. Apply the version

```bash
relicta bump
```

Review the proposed version and configured version-file changes before continuing. Use `relicta bump --help` to see version-selection options supported by the installed release.

### 3. Generate notes

```bash
relicta notes
```

The default notes are deterministic and based on repository history. In v4.2.0, `--ai` enables provider-generated prose when a provider is configured. `-a` is the short form of `--audience`, not an AI switch.

```bash
relicta notes --ai --audience public --tone professional
```

Options also include `--language`, `--emoji`, and `--output`. Review all generated claims before approval. Drafting customer notes with product context from a coding-agent conversation and saving that draft through MCP is a v5 source capability, not part of v4.2.0.

### 4. Approve

```bash
relicta approve
```

Review the prepared release. `--edit` opens the notes in an editor; `--interactive` opens the approval interface. `--yes` approves without an interactive prompt, so use it only when your configured governance policy and surrounding controls permit it.

### 5. Publish

```bash
relicta publish
```

Publishing performs configured release actions. v4.2.0 provides `--skip-tag`, `--skip-push`, and `--skip-plugins` for workflows where another system owns those actions. `--skip-approval` bypasses Relicta's approval check and should only be used when an equivalent external gate is in force.

## Configuration and safety

The current configuration file is `.relicta.yaml`. Use `relicta init` to create it, then review versioning, governance, Git, and publisher settings before running a live release.

`--dry-run` previews a command; it is not a substitute for reviewing external effects configured by publishers. See the [configuration guide](/configuration) and the [v4.2.0 CLI reference](https://github.com/relicta-tech/relicta/tree/v4.2.0/docs/cli) for the exact release command contract.
