The [Relicta GitHub Action](https://github.com/relicta-tech/relicta-action) installs the CLI and can run release commands in a workflow. Its default command is `full`, which runs the release workflow. Treat that as a publishing action: protect the workflow and repository credentials accordingly.

```yaml
name: Release
on:
  workflow_dispatch:

jobs:
  release:
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@11d5960a326750d5838078e36cf38b85af677262 # v4
        with:
          fetch-depth: 0
      # Pin the action to a reviewed commit; update this SHA deliberately.
      - uses: relicta-tech/relicta-action@0268e9a3001e9483874e5501d59fa929a42130f3 # v2
        with:
          version: v4.2.0
          command: plan
          github-token: ${{ secrets.GITHUB_TOKEN }}
          dry-run: true
```

This example runs a plan preview on demand and does not publish. To execute a release, change the command deliberately and review the action's approval and dry-run settings first. The action's current metadata sets `auto-approve` to `true` by default, so do not assume an interactive approval prompt will protect an automated run.

## Action inputs

The action metadata currently documents these inputs:

- `version`: Relicta CLI version to install.
- `command`: `full` (default), `plan`, `bump`, `notes`, `approve`, `publish`, or `custom`.
- `github-token`: token used for GitHub release operations.
- `config` or `config-content`: configuration file path or inline YAML.
- `auto-approve`: automatically approve a release; currently defaults to `true`.
- `dry-run`: simulate actions; defaults to `false`.
- `working-directory`: directory for the command; defaults to `.`.
- `plugins`: comma-separated plugin names to download; defaults to none.

The action version in the example is pinned to the reviewed v2 commit. Confirm its inputs and behavior in that revision's [action metadata](https://github.com/relicta-tech/relicta-action/blob/0268e9a3001e9483874e5501d59fa929a42130f3/action.yaml) before relying on them, and review updates before changing the pin. The CLI's default config filename in v4.2.0 is `.relicta.yaml`.

## Secrets and permissions

- Store provider and plugin credentials as encrypted repository or environment secrets.
- Grant only the permissions the selected command needs. Release publication requires write access.
- Fetch full history and tags when your release plan depends on earlier commits or tags.
- Protect release workflows with branch rules and GitHub environment reviewers when human review is required.

For a manual release, prefer a protected `workflow_dispatch` job or a staged plan and publish workflow that your team can review. A successful plan is not approval to publish.
